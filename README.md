# ИИ-диспетчер обращений — стартовый набор

**Цель:** сделать небольшое веб-приложение, которое читает вымышленные обращения в школьную службу помощи, предлагает категорию и срочность, а человек может исправить решение.

На работу есть три занятия по 120 минут. Работайте командой из 3–4 человек. Примеры обращений должны быть вымышленными: не вводите имена, телефоны и реальные школьные данные.

## Что понадобится

- Компьютер с Python 3.10+ и доступом в интернет.
- Редактор кода, например VS Code, либо любой текстовый редактор.
- Терминал и современный браузер.
- Наставник настраивает ключ AllTokens на компьютере. Ключ не копируется в HTML, JavaScript, сообщения, скриншоты или Git.

Если Python или Flask не запускается, сразу сообщите наставнику. Не тратьте занятие на самостоятельную установку окружения.

**До первого занятия, 15–20 минут:** прочитайте разделы «Правила диспетчера» и «Как устроены файлы» ниже. В [примере запроса AllTokens](https://docs.alltokens.ru/api/chat-completions/) найдите `messages` и `choices[0].message.content`. Подумайте, почему ответ модели нужно проверять и зачем человеку оставлена возможность исправления.

## Запуск

Откройте терминал в папке набора и выполните:

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 app.py
```

На Windows активация: `.venv\Scripts\activate`, запуск: `py app.py`. Откройте `http://127.0.0.1:5000`.

Без ключа приложение работает в учебном режиме: всегда возвращает «другое / обычный». Это позволяет собирать интерфейс. Когда наставник настроит ключ, переключите `DISPATCHER_DEMO` на `0` и проверьте живой запрос. Не записывайте ключ в файл проекта.

## Правила диспетчера

Категория — ровно одна из четырёх:

1. `техника` — компьютеры, проекторы, принтеры, звук;
2. `сеть` — интернет, Wi-Fi, вход в школьный сервис;
3. `помещение` — свет, мебель, дверь, температура;
4. `другое` — всё остальное или непонятное.

Приоритет: `высокий`, если в тексте явно сказано, что из-за проблемы прямо сейчас нельзя провести занятие или затронуто несколько кабинетов. В остальных случаях `обычный`. Если непонятно, что именно сломано или где это произошло, предложите **один** короткий уточняющий вопрос. Не придумывайте отсутствующие подробности.

Формат результата в программе:

```json
{"category":"техника","priority":"обычный","question":"В каком кабинете не работает проектор?"}
```

## Как устроены файлы

- `app.py` — локальный сервер. Браузер обращается только к нему.
- `alltokens.py` — готовый серверный вызов AllTokens. Ключ берётся из переменной окружения.
- `dispatcher.py` — **ваша главная задача:** составить инструкцию модели, разобрать её ответ и проверить значения.
- `static/index.html` — интерфейс; добавьте ручное исправление результата.
- `cases_training.json` — примеры, на которых можно разрабатывать решение.
- `evaluate.py` — проверка на новых примерах. Наставник выдаст `cases_test.json` на третьем занятии.

## Работа по занятиям

### День 1: правила и первый запрос

1. Запустите приложение. Убедитесь, что оно открывается в браузере.
2. Разберите 12 примеров в `cases_training.json`. Если не согласны с эталоном, запишите причину и обсудите с наставником.
3. Допишите в `dispatcher.py` инструкцию модели. Попросите её вернуть только JSON с полями `category`, `priority`, `question`.
4. Вызовите модель через готовую функцию `chat`. Найдите текст в `choices[0].message.content`, превратите его в JSON и проверьте допустимые значения.
5. Покажите наставнику один живой запрос и один случай, когда нужен уточняющий вопрос.

**Готово за день:** приложение запущено, правила согласованы, живой ответ API виден в интерфейсе.

### День 2: продукт и ручная проверка

1. Обработайте все учебные обращения. Сохраните результаты в таблице интерфейса.
2. Добавьте возможность вручную изменить категорию и приоритет в строке таблицы. Рядом сохраните первоначальный ответ модели: исправление не должно его стирать.
3. Покажите сообщение об ошибке, если сеть или API недоступны. Приложение не должно исчезать или зависать.
4. Сравните решения модели с учебными эталонами. Запишите минимум две ошибки или спорных случая.

**Готово за день:** ввод → ответ модели → таблица → ручное исправление работают целиком.

### День 3: независимая проверка и показ

1. Получите от наставника `cases_test.json` и положите рядом с `evaluate.py`.
2. При запущенном сервере выполните `python3 evaluate.py cases_test.json`.
3. Запишите число верных категорий и приоритетов из 12. Доля считается как `верно / 12`; неверный или пустой ответ тоже ошибка.
4. Разберите минимум два неверных ответа: какой текст ввёл пользователь, что ответила модель, как исправил бы человек.
5. Подготовьте демонстрацию на 3 минуты: один обычный случай, один случай с уточнением, одно ручное исправление и результат проверки.

**Готово за день:** работает демонстрация и есть честный отчёт об ошибках. Высокая точность сама по себе не является условием зачёта.

## Роли

| Роль | Свой результат |
|---|---|
| Данные и правила | Проверенные примеры, понятные границы категорий и приоритета |
| API и логика | Промпт, разбор JSON, проверка ответа, обработка ошибки |
| Интерфейс | Таблица, понятные состояния загрузки и ошибки, ручное исправление |
| Проверка | Запуск проверки, подсчёт результатов, разбор ошибок |

В команде из трёх объедините «Данные и правила» с «Проверкой». Обсуждать решения должны все; за компьютером можно меняться после каждого короткого этапа.

## Если закончите раньше

- Сравните два варианта инструкции модели на **одном и том же** наборе из 12 обращений.
- Добавьте фильтр таблицы по категории или приоритету.
- Позвольте повторить классификацию после ответа на уточняющий вопрос.
- Посчитайте отдельно ошибки категории и приоритета.

## Справка

AllTokens использует `POST /api/v1/chat/completions`; пример запроса и коды ошибок есть в [официальной документации](https://docs.alltokens.ru/api/chat-completions/). Для этого набора сетевой код уже написан в `alltokens.py`.
